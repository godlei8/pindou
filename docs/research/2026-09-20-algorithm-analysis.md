# 拼豆图纸生成 · 算法分析与优化

日期：2026-09-20
性质：设计输入文档。回答两个问题：市面工具的算法差在哪里；我们每个环节该用什么算法、为什么。
调研方式：三路并行——① 逐行阅读 10+ 个开源拼豆工具源码及 Issues；② 中英文社区用户痛点收集；③ 像素化 / 量化 / 抖动 / AI 生成 / 邻近领域（十字绣、钻石画、LEGO 马赛克）的论文与工具方法调研。原始报告六份，本文是结论层；关键论断均附来源。

## 1. 市面工具的算法现状：共性缺陷

逐行读完 Zippland/perler-beads（965★）、LunarXuan/Pindo（400★）、pgp00/beadrelief（313★）、liangdabiao/perler-beads-ai（306★）、zwhy149/bead-grid-studio（175★）、Jett-Wu（50★）等十余个项目的源码后，缺陷高度收敛：

| # | 缺陷 | 典型表现 | 后果 |
|---|---|---|---|
| 1 | **色数限制 = 事后截断，而非误差最小化** | Pindo 按使用频次取前 N；bead-grid-studio 按 count·d² 贪心并色；Zippland 按频次阈值全局合并。无一先聚类再映射 | 小面积关键色（眼睛高光、细描边）被吞；大面积渐变被硬切出断层 |
| 2 | **色差度量随意且不一致** | redmean RGB（beadrelief）、Oklab（Zippland）、CIEDE2000（Pindo）、匹配和合并两套空间混用（bead-grid-studio）；合并阈值（0.30 / 0.10 Oklab）无 JND 依据 | 肤色偏色、近色误并 |
| 3 | **下采样 gamma 错误** | 仅 Pindo 与 bead-grid-studio(photo) 在线性 RGB 平均，其余全在 sRGB 空间平均或 canvas drawImage | 暗部偏亮、边缘发灰 |
| 4 | **"主色"实现粗糙** | Zippland 用精确 RGB 三元组众数——JPEG 每格几乎无重复三元组，"主色"退化为随机像素 | 照片模式效果崩坏的直接根因 |
| 5 | **可拼性检查缺席或默认关闭** | Pindo 的孤岛清理需手动开且限 ≤58 格；beadrelief 的 speckleReduction 默认 0；多数项目完全没有 | 散点、断线、悬空全靠用户肉眼 |
| 6 | **抖动与清理二选一** | 有抖动的项目在 sRGB 空间扩散误差；清理逻辑仅在无抖动时生效（pixel-to-beads） | 开抖动 = 放弃可拼性 |
| 7 | **色卡数据不可靠** | pixel-to-beads 的 MARD E2 色值写成 `#FECODF`（字母 O），开放 9 个月未修；Zippland Issue #2 用户质疑色号 RGB 无出处 | **算法再好也被错色卡抵消** |
| 8 | 背景/透明处理各自为政 | alpha 阈值 128 / 24 / 0.12 / 丢弃 / 置白 / 完全忽略（Pindo 生成路径） | 透明边缘出深色杂边 |
| 9 | 底板分片停留在 `ceil(w/29)` 几何切块 | 无项目考虑避开细节切缝 | 接缝穿过人脸 |
| 10 | 参数即魔法数、无基准 | bead-grid-studio 单函数 1503 行、≥60 个手调阈值；bead-grid #12 承认基准未发布 | 用户反馈无法转化为回归测试 |

**一句话总结：没有任何一个项目完整走过"正确下采样 → 聚类选色 → 色卡受限分配 → 可拼性约束"这条链路。** 这就是我们的算法机会窗口。

邻近领域的对照也支持这个判断：老牌十字绣商业软件（PCStitch、Pattern Maker、WinStitch）同样没有自动散点处理，而把"邻域分组后再匹配线色"做成核心卖点的新一代工具（Stitchmate、Xstitchify）正是靠这一点差异化——Stitchmate 宣称散点减少约 79%（厂商数据，未独立验证）。

## 2. 用户痛点：真实反馈 → 算法决策的映射

来源：中国区 App Store 14 款拼豆 App 1356 条评论（筛出 261 条质量相关）、Reddit 五个相关版块（经归档镜像）、GitHub issues、V2EX、贴吧、微博、B 站，以及十字绣/钻石画社区。软文已剔除。完整引文见 `raw/B-user-painpoints.md`。

高频痛点（≥4 个独立来源）及本文档的回应：

| # | 痛点（用户原话摘录） | 根因 | 对应决策 |
|---|---|---|---|
| 1 | **色号与实物不符**——"鹅黄色识别为绿色？？？？""脸都变成绿色的了""灰色键帽识别成紫色"。App Store 差评第一大类 | RGB 欧氏距离 + 色卡数据本身错误 | §4.2 色差决策 + 自建色卡 |
| 2 | **杂色/散点**——"一大片肤色里飘着 3 颗浅紫、2 颗橄榄绿…为这几颗专门下一单？运费都比豆贵" | 逐格独立匹配 | §3.3 graph cut + 小色号合并 |
| 3 | **尺寸两难**——"要么颜色乱成一团，要么糊成一坨，完全不像了" | 朴素下采样在小网格崩坏 | §3.1 下采样分派 + 尺寸推荐（§4.5） |
| 4 | **AI 出图不可拼**——"网格大小不一互相挤压""半颗豆""豆子中途换色"。B 站总结为三大天坑：伪像素网格、色彩污染、抗锯齿柔化色 | 拿 AI 原图直接用，无网格对齐后处理 | §3.5 强制走网格检测 + 色卡吸附 |
| 5 | **随机冒出原图没有的颜色 / 灰色毛边** | sRGB 均值池化在色边界造中间色 | §3.1 线性空间 + 众数；graph cut 数据项压制 |
| 6 | **打印比例对不上板子**——"打印出来的图纸和实际大小严重不符" | 导出不按 1:1 物理尺寸 | spec §4.6 已定 1:1 PDF；§4.5 渲染规则 |
| 7 | **色卡不全 / 只想用自己有的色**——"我的豆子只有72色…不是所有人都有全套" | 色卡按品牌整卖，无套装/库存过滤 | 数据模型 `in_sets` 已备；库存约束列 v2 |
| 8 | **悬空细部熨烫塌陷**——"头发尖、花瓣末梢悬空…熨斗一压直接瘫平"。社区解法：补透明豆当桥 | 无结构检查 | spec §4.3 体系 + 修复动作新增"补透明豆桥"（§4.5） |
| 9 | **生成后不可编辑**——"一张不能编辑的图纸，就像一张死图" | 工具只做转换不做编辑 | spec 目前仅有 apply-patch，缺口见 §4.5 |
| 10 | **色号/网格看不清**——"1pt 线被抗锯齿摊成一层灰雾""编号顶到格子上两边连在一起" | 渲染实现粗糙 | §4.5 渲染可读性规则 |

两个额外的定性发现：

- **社区反感"AI 直出图"，但不反感算法转换。** r/PerlerBeads 有 522 赞的帖子抨击"看起来对、实际拼不了"的 AI 图；同时"Photoshop 式像素化转换不算 AI"获得正面共识。启示：AI 重绘的输出必须经过我们的网格对齐 + 可拼性流水线才见人，且成品展示应强调"每格可拼、色号真实"。
- **头部竞品（拼豆咔、一豆成画、刀盾拼豆、MakeBead、BeadFuse）找不到任何独立真实用户评价**，能搜到的全是厂商软文。市场声量 ≠ 质量口碑，这个赛道还没有公认的"好用"标杆。

个别提到但可直接转化为测试用例的：纯色块被吃只剩轮廓、透明像素变黑/变白、非方形图被拉伸、水印被识别进图纸、8×8 分格与板子 10/5 格刻度错位（→ §5 黄金样本）。

## 3. 技术方法版图（调研精要）

### 3.1 下采样

| 方法 | 特点 | 50–100 格下表现 | Python 可用性 |
|---|---|---|---|
| Pillow BOX / bicubic | 面积平均 | 模糊（Gerstner 论文的对照基线） | 现成 |
| 最近邻 | 随机采样 | 断线、锯齿（Fusible-Beads-Studio 1024→29 的教训） | 现成 |
| Kopf 2013 内容自适应 | 可变形双边核 EM 迭代，线条保持细且连通 | 极佳，论文亲测卡通→像素画 | 无成熟实现，需自写且慢 |
| Öztireli 2015 感知下采样 | SSIM 闭式解 | 好，但噪声被当细节放大 | 十几行 NumPy 可复现 |
| DPID 2016 | 细节加权单遍 | 好，同样噪声敏感 | numba 移植存在（未充分测试） |
| **Gerstner 2012 联合优化** | SLIC 超像素 + 调色板确定性退火，**专为 11×16~64×64 + ≤16 色设计** | 该尺度下最稳，用户研究优于基线 | 无成熟实现，算法不长可自写（numba） |
| unfake 式网格检测 + 众数 | Sobel 投影找网格相位，dominant 采样 | 对"伪像素图"（AI 输出/放大过的像素图）是唯一正解 | `pip install unfake`，支持 fixed_palette |

### 3.2 量化与色号匹配

- 量化算法排位（Pérez-Delgado & Celebi 2024，10 算法 × 8 项质量指标）：median cut **全面垫底**（而它是 Pillow 默认），k-means 系最佳。
- 映射策略三档：逐像素直接匹配（散点与色数爆炸之源，市面工具的普遍做法）→ 先聚类再映射簇心（Stitchmate 路线，缺点是两个簇心可能映射到同一色号）→ **色卡受限 k-medoids（簇心直接限定 ∈ 色卡）**，一步到位，无去重问题。scikit-learn-extra 有现成 KMedoids，自写 Lloyd 变体也仅几十行。
- 色差公式：CIEDE2000 是小色差的标准（Sharma 2005 有 34 组官方测试数据可钉死实现）；OKLab 欧氏连续、快、蓝区色相优于 CIELAB；HyAB 论文显示对 >10 单位的大色差优于 ΔE00——实体色卡稀疏、最近色常是大色差，值得做 A/B。针对"匹配实体色卡"场景的公式对照研究是空白，没人做过。

### 3.3 散点抑制：graph cut 是被验证过的答案

这是全部调研中最有价值的发现。**LEGO 马赛克论文 Pixel2Brick（CGF 2015, DOI 10.1111/cgf.12772）解的问题与拼豆几乎同构**：把图像映射到 26 色固定 LEGO 色板，同时要求空间连贯。做法：

- 多标签 graph cut（α-expansion，Boykov-Veksler-Zabih 2001）：标签 = 色号，数据项 = ΔE(格子颜色, 色号)，平滑项 = λ·[相邻格标签不同]（Potts 模型）
- 一次优化同时完成"逐格选色号"与"抑制散点"，且天然保边——边界两侧色差大，数据项压过平滑项
- 之后检测悬空块，2×2 局部改色修连通

Python 有现成实现（pyGCO / PyMaxflow，后者教程就有网格 Potts 示例）。100×100 格 × 50 标签，α-expansion 数十毫秒到 1 秒——完全在我们同步调参接口的预算内。

对比：市面工具的散点处理全是**事后清理**（多数滤波、小连通块合并），会磨掉眼睛高光这类合法孤点；graph cut 是**生成时预防**，λ 一个参数控制"保真 vs 平整"的连续权衡。二者可叠加：graph cut 打底，面积过滤兜底。

### 3.4 抖动

十字绣/拼豆社区共识 + 工具证据都指向：**手工拼贴场景默认禁用误差扩散**（散点 = 工时×3 + 熨烫易倒）。若用户要渐变：只在低梯度大面积区施加低幅有序/蓝噪声抖动（借 pngquant 的"选择性抖动"门控思想），抖后仍跑最小连通域约束。输出 **confetti%**（无同色邻居格子占比）指标——十字绣领域的经验标定：<2% 可接受，>10% 极难做。

### 3.5 AI 重绘

- 核心结论：**扩散模型无法直接输出真像素网格**（连续潜空间没有离散像素概念）。社区公认流程：生成 8× 过采样"伪像素图" → 网格检测对齐 → 众数下采样 → 色卡吸附。`unfake.py` 一个库覆盖后三步，且支持 `fixed_palette` 直接传拼豆色号。
- 提示词要素（多个模型卡与教程收敛）：正向 `pixel art, simple, flat colors, limited palette, solid background`；负向 `3d render, realistic, blurry, photograph`；即梦系再叠"像素风格插画，线条简洁，色彩明快，8-bit 色彩质感"（Datawhale 教程实测措辞）。
- 国内模型现状：即梦图生图 3.0（`jimeng_i2i_v30`，单图 + 指令 + scale 强度）、通义万相 `wanx2.1-imageedit`、可灵 v3 都能做参考图风格化，但**都没有像素风专项接口**——所以后处理（网格检测 + 色卡吸附）必须自建，这恰好是我们流水线本来就有的环节。
- 均值下采样会在伪像素图上产生新颜色，必须用众数/dominant——这与 3.1 的结论一致。

## 4. 我们的算法方案

### 4.1 总流水线

```
输入图
 ├─ A. 判定输入类型（像素图检测：unfake 式网格探测）
 │
 ├─ B. [可选] AI 重绘（照片 → 伪像素/平涂插画）
 │      国内 i2i + 像素风提示词 → 输出仍按"伪像素图"走 C2
 │
 ├─ C. 下采样（按输入类型分派）
 │      C1 卡通/插画/照片：双边预滤波 → 线性 RGB 面积平均
 │      C2 像素图/AI 伪像素图：网格检测对齐 → 格内众数
 │
 ├─ D. 选色：色卡受限 k-medoids（OKLab 距离，簇心 ∈ 色卡，k ≤ 用户色数上限）
 │      → 产出本图的"工作色板"（≤N 个真实色号）
 │
 ├─ E. 分配：多标签 graph cut（α-expansion）
 │      数据项 = ΔE00(格子, 色号)，平滑项 = λ·Potts
 │      λ 暴露为"平整度"滑块（0 = 纯最近色，等价市面工具行为）
 │
 ├─ F. 约束后处理
 │      小色号合并（< 阈值颗数并入最近色）→ 悬空/对角虚连修复建议 → 连通域体检
 │
 └─ G. 渲染导出 + confetti% / 可拼性评分
```

### 4.2 逐环节决策与依据

| 环节 | 决策 | 依据 | 淘汰了什么 |
|---|---|---|---|
| 下采样 | 线性 RGB 面积平均（卡通/照片）+ 网格检测众数（像素图） | 缺陷 #3/#4；unfake 实践 | sRGB 平均、最近邻、精确三元组众数 |
| 预滤波 | 双边滤波，照片档可加大半径 | 压噪防止面积平均造中间色 | mean-shift（参数敏感且慢） |
| 选色 | **k-medoids，簇心限定 ∈ 色卡，OKLab 距离** | 量化文献 k-means 系最佳 + 免去"簇心映射同色号去重" | 频次截断（缺陷 #1）、median cut（文献垫底） |
| 分配 | **graph cut + Potts 平滑** | Pixel2Brick 同构问题已验证；生成时预防优于事后清理 | 逐格独立最近色 + 多数滤波 |
| 色差 | 聚类/数据项用 OKLab 欧氏；最终决策与合并阈值用 CIEDE2000（Sharma 34 组测试对钉死实现）；HyAB 留作实验开关 | 3.2 节 | colormath（停维护、逐点循环） |
| 抖动 | 默认关；开启时仅低梯度区 + 有序/蓝噪声 + 抖后连通域约束 | 社区共识 + confetti 标定 | 全图 Floyd-Steinberg |
| 合并阈值 | ΔE00 < 2 无条件合并；占比极小的色放宽到 < 5 | JND ≈ 1.0 ΔE00；Stitchmate 实操规则 | 0.30 Oklab 这类无依据阈值 |
| AI 重绘 | i2i + 收敛提示词模板 → 一律按伪像素图后处理 | 3.5 节 | 期望模型直出可用网格 |
| 可拼性 | spec §4.3 的连通域体系不变，新增 confetti% 指标与热图分级（同色邻居数 0/1/2+） | Stitchmate ConfettiScope + 2%/10% 标定 | — |
| 孤点保护 | 用户可标记"保留孤点"（眼睛高光），清理与 graph cut 对标记格加保护约束 | 业界共识：无算法能全自动分辨高光与噪点 | 全自动清理 |
| 色卡 | **自建，每色标注出处**；基底 = maxcleme/beadcolors（含 Lab）× Zippland colorSystemMapping.json 交叉校验，冲突处标记待实测 | 缺陷 #7：算法改进会被错色卡抵消 | 直接抄单一来源 |

### 4.25 从痛点直接导出的补充要求

痛点报告带来四条第 3 节方法调研覆盖不到的要求：

1. **修复动作库加入"补透明豆桥"。** 悬空细部的社区标准解法不是删格子，而是在空隙里塞透明豆（MARD T01 / Perler Clear）当结构桥，熨完几乎隐形。我们的修复建议应把它作为悬空/虚连问题的**首选动作**（保形），"并入邻色/删除"作次选（改形）。
2. **渲染可读性规则**（全部来自真实抱怨）：网格线必须落在整数像素上（1pt 线被抗锯齿摊成"灰雾"是实际投诉）；色号文字留边距不顶格；空格/透明格的色号可隐藏；辅助线按板子刻度每 5 格虚线、每 10 格实线；相近色号避免使用相近的标注符号（十字绣软件的成熟规则）。
3. **尺寸推荐**：生成时同时算 2–3 个候选格数的缩略预览，标注"这个尺寸下哪些细节会丢"。钻石画行业已有硬经验（单人脸至少约 64×80 格），流水线足够快，多算两档几乎零成本。
4. **描边保护**：卡通图的黑轮廓被匹配成杂灰是高频抱怨。v1 用轻量方案——检测暗色细线格，在 graph cut 中锁定其标签为最近的深色色号；十字绣的"描边独立图层"完整方案列 v2。

另有一个**产品缺口**超出算法范围需要决策：spec 目前只有"逐条 apply/reject 修复建议"，没有自由编辑（画笔/油漆桶/吸管）。"生成后不可编辑 = 死图"是十大痛点之一，竞品差评反复出现。是否把最小编辑能力（单格改色 + 油漆桶）提进 v1，留给需求方定。

### 4.3 分期

**v1（进实现计划）**：C1/C2 双路下采样、k-medoids 选色、graph cut 分配（λ 滑块）、合并与体检、confetti%、AI 走"国内 i2i + unfake 式后处理"、自建色卡；加上 §4.25 的补透明豆桥、渲染可读性规则、尺寸推荐、轻量描边锁定。以上每项都有现成库或几十行级自写实现，无研究风险。

**v2（实验轨，攒够反馈再动）**：Gerstner 2012 联合优化复现（把 D+E 合并为一次退火求解，理论上限更高但要自写 + numba 调优）；HyAB 色差 A/B；蓝噪声受限抖动；按用户库存约束选色（brickMosaic 思路：每色只有 N 颗）；描边独立图层完整方案。

**明确不做**：SD-πXL（论文直接面向拼豆但需 24GB 显卡 + 分钟到小时级，只配离线精品场景）；本地 Stable Diffusion 链路（我们已定国内 API 路线）；深度学习像素化模型（许可、训练、部署成本都不划算）。

### 4.4 对 spec 的回填

本文确定后，spec 需更新：① §4.1 "k-means 聚类后匹配色号" → "色卡受限 k-medoids"；② 新增分配阶段 graph cut 与 λ 参数，用户参数扩为"格数/色数/平整度 λ/抖动"；③ §4.3 可拼性表新增 confetti% 指标；④ §4.4 修复动作库加入"补透明豆桥"并列为悬空类问题首选；⑤ §4.6 渲染补充可读性规则（整数像素网格线、编号边距、空格色号可隐藏、5/10 格刻度）；⑥ 新增尺寸推荐。数据模型无需改动（params/buildability 均为 JSONB，天然容纳新字段）。待需求方决策：最小编辑能力（单格改色 + 油漆桶）是否进 v1。

## 5. 评测与基准

缺陷 #10 的反面教训：没有基准，一切优化都是玄学。

- **黄金样本**：卡通、Logo、真人照片、已有像素图、构造的对角虚连图、渐变图，各固定参数存 grid 快照做回归。另按真实投诉补五个专项用例：大面积纯色块图（防"色块被吃只剩轮廓"）、灰色物体（防灰→紫偏色）、鹅黄色物体（防黄→绿）、带透明通道 PNG（防透明变黑/变白）、非正方形图（防拉伸变形）。
- **量化指标**：confetti%（目标 <2%）、总色数、平均/最大 ΔE00（对原图）、4-连通组件数、单格宽区域占比、小色号数量。每次算法改动跑全量指标，好坏用数字说话。
- **对照组**：同一张图跑"λ=0 纯最近色"模式即等价市面工具，天然的 before/after 对比素材。
- **实拼反馈闭环**：feedback 表的格子级标注 → 定位评分权重与 λ 默认值的偏差（spec §5 已备）。
