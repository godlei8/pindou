# 从进站到出图：入口流程调研

> 2026-09-21。起因：项目页那个原生「选择文件 / 未选择任何文件」加一个表单，既丑又绕。
> 方法：直接读各产品的源码或首屏原文，不看二手评测。

---

## 1. 我们现在的流程

```
进站 → 项目页 → 选文件（浏览器原生控件）→ 填项目名（可选）→ 点「上传」
     → 项目出现在列表里 → 点进去 → 工作台 → 才开始出图
```

**看到第一张图纸之前要 4 次操作 + 1 次跳页。** 另外：

- 原生文件控件破坏整站像素风，而且"未选择任何文件"是浏览器的文案，不是我们的
- 「上传」在没选文件时显示成一块发白的禁用按钮，看着像坏了
- 项目列表只有文件名，两个 `avatar.jpg` 完全分不出哪个是哪个
- 不能拖拽，不能粘贴

## 2. 别人怎么做

| | 首屏主角 | 拖拽 | 粘贴 | 示例图 | 传完即见结果 | 上传前要填东西 |

| **Squoosh**（Google） | 居中大按钮 | ✅ 整页可投 | ✅ 真按钮，调剪贴板 API | ✅ 4 张 | ✅ 直接进编辑器 | ❌ |

| **belleqaq**（拼豆） | 编辑器就是首页 | ✅ | ❌ | — | ✅ | ❌ |
| **Pixel It** | 预载一张默认图 | ❌ | ❌ | ✅ 默认图 | ✅ 实时 | ❌ |

## 3. 结论

五个参照物在这几件事上**完全一致**，不存在需要权衡的分歧：

1. **上传本身就是开始干活，不是一个独立的管理步骤。** 拿到图就直接进编辑器看结果。
2. **出结果之前不问任何问题。** 没有一家在上传前要你起名。名字默认用文件名，事后能改。
3. **三种投图方式并存：点选、拖拽、粘贴。** 粘贴对我们的用户尤其重要——
   拼豆图大多是从小红书/微博截图来的，截完 Ctrl+V 是最短路径。
4. **没图的人给示例图。** 消除"我得先去找张图"的门槛，也顺便演示这工具能干什么。
5. **整页都能投**（Squoosh），不必精确瞄准一个框。

## 4. 我们不能照抄的地方

参照物大多是**无状态**的（刷新就没了），我们有账号和持久化的项目。所以要把
"即时"和"持久"合起来：

- **投图 = 建项目 + 立刻跳进工作台**，工作台自己会出第一张图纸（这条路径早就有了）。
- 项目列表变成「最近的图纸」，**必须带缩略图**——重新进站的人靠的是认图，不是认文件名。
- **AI 不进入口。** 参照物里没有一家在上传时让你选一个又贵又慢的可选步骤；
  放进入口就等于在出结果前又加了一个问题。AI 继续留在工作台里按需触发。

## 5. 目标流程

**新图：一步到图纸**

```
进站 → 拖 / 粘贴 / 点选 / 点示例图 → 工作台（图纸已出）
```

**回来接着做：一步回到上次**

```
进站 → 点最近图纸的缩略图 → 工作台（载入最新版本）
```

首页同时服务这两种人：上面是投图区，下面是带缩略图的最近图纸。
一个项目都没有时，投图区占满视线并附示例图；有项目后投图区收成一条，把位置让给缩略图。
